# 構成と検証の境界

## 目標とする処理

1. ブラウザでルームを作成する。
2. 参加者がプロンプトを投稿する。
3. サーバーがルームの権限、期限、生成の価格と予算を確認する。
4. 外部の生成サービスで音楽・映像を生成し、非公開R2へ保存する。
5. Containersで素材の整合性、音声の接続、再生用データを検証する。
6. 大画面のブラウザで再生し、実際の再生結果をサーバーへ通知する。

## 各サービスの役割

| サービス | 役割 |
| --- | --- |
| Workers | 画面配信、HTTP受付、権限確認 |
| D1 | ルーム状態、実行履歴、生成費用の予約 |
| R2 | 非公開の素材・生成物 |
| Containers | Node.js / Python / ffmpegによる音声・映像処理 |

ルーム間の操作権限を分離し、同じ処理の再送で有料生成を重複実行しない。
費用予約は再起動後も残し、失敗や結果不明の処理を自動的に未実行扱いに戻さない。

## 未完了の接続

D1はルーム作成、予算予約、状態の更新競合の基礎実装まで。
生成の実行許可・履歴・再生状態を含む処理全体は移植中。
R2から生成サービスへの限定的な素材受渡し、Containersとの接続、Workersの配備用構成は未完了。
`cloud/server/`にはPostgreSQL向けの接続が含まれるため、そのままCloudflare本番用として配備しない。

## 検証で区別するもの

- 合成データの単体・統合テスト
- ffmpegを使う音声・映像のローカル処理
- ブラウザの入力と画面遷移
- 実際の有料生成
- 配備先での連続再生
- 別端末での利用

前段の成功だけで後段まで完了したとは扱わない。
