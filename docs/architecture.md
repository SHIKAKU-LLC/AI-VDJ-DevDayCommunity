# 構成と検証の境界

## 目標とする処理

1. ブラウザでルームを作成する。
2. 参加者がプロンプトを投稿する。
3. サーバーがルームの権限、期限、生成の価格と予算を確認する。
4. 外部の生成サービスで音楽・映像を生成し、非公開R2へ保存する。
5. Containersで素材の整合性、音声の接続、再生用データを検証する。
6. 大画面のブラウザで再生し、実際の再生結果をサーバーへ通知する。

## 各サービスの役割

| サービス | 役割 |
| --- | --- |
| Workers | 画面配信、HTTP受付、権限確認 |
| D1 | ルーム状態、実行履歴、生成費用の予約 |
| R2 | 非公開の素材・生成物 |
| Containers | Node.js / Python / ffmpegによる音声・映像処理 |

ルーム間の操作権限を分離し、同じ処理の再送で有料生成を重複実行しない。
費用予約は再起動後も残し、失敗や結果不明の処理を自動的に未実行扱いに戻さない。

## 未完了の接続

D1のルーム作成・参加・投稿・受付の切替を、既存の画面から利用できる段階まで実装した。
同じ操作の再送、他ルームの権限、更新競合、期限切れを検証している。
Workersの画面配信とローカルビルドも接続済み。Cloudflare上の検証環境へ配備し、Containerでの合成音声処理を確認した。本番への配備は未実施。
生成の実行許可・履歴・再生状態を含む処理全体は移植中。
R2の単一素材を期限・取得回数付きで渡す処理は単体検証済み。生成サービスからの実取得とContainersとの接続は未完了。
検証環境の実測は [Cloudflareの検証記録](cloudflare-staging-check.md) に記載する。
`cloud/server/`は注入するHTTP・権限・CPU処理の共通部品を保持する。旧バックエンドの起動・配備経路は撤去済みであり、現行の入口は`cloud/cloudflare/`にある。[撤去範囲と保持した共通部品](development.md#旧バックエンドの撤去)を参照する。

現在のWorkersは受付専用として動作し、生成・自動DJ・再生の準備完了を返さない。
Cloudflare用の起動方法と未完事項は[Cloudflareの手順](../cloud/cloudflare/README.md)に記載する。

## 検証で区別するもの

- 合成データの単体・統合テスト
- ffmpegを使う音声・映像のローカル処理
- ブラウザの入力と画面遷移
- 実際の有料生成
- 配備先での連続再生
- 別端末での利用

前段の成功だけで後段まで完了したとは扱わない。
