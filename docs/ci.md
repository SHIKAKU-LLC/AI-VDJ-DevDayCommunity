# 自動テストの待ち時間

## 確認した所要時間

標準2CPU環境での[初回実行](https://github.com/SHIKAKU-LLC/AI-VDJ-DevDayCommunity/actions/runs/39055232886)と[2並列への変更後](https://github.com/SHIKAKU-LLC/AI-VDJ-DevDayCommunity/actions/runs/39056029447)は、全項目が成功した。以下は8コア環境の計測値ではない。

| 確認 | 変更前 | 2並列へ変更後 |
| --- | --- | --- |
| ファイル検査・Python | 48秒 | 47秒 |
| ブラウザ・ルーム | 4分26秒 | 6分17秒 |
| 音声解析・処理連携 | 6分52秒 | 4分27秒 |

ブラウザ・ルームのうち4分17秒がテスト本体、依存関係の導入は約3秒だった。現時点ではダウンロードの再利用より実行の並列化を優先する。

音声解析・処理連携は短縮した一方、ブラウザ・ルームは長くなった。並列数を増やすだけで全試験が速くなるとは限らないため、実行環境を変更した際は両方を測定する。

## 設定

- ブラウザ・ルームと音声連携は、`ubuntu-24.04-8core`でそれぞれ4ファイルずつ実行する。実際に8CPU以上であることをジョブの開始時に検査する。
- ファイル検査・Pythonのジョブは標準ランナーを使う。
- 同じブランチ・PRへの新しい更新が来たら、古い実行を停止する。
- 音声処理内部の計算スレッドは1にし、過剰な並列化を避ける。
- 試験の一覧は維持する。有料ジョブは同じリポジトリ内のブランチに限定し、外部forkのPRでは標準ランナーの検査だけを実行する。
- 数値・音声の試験を工程別に表示し、遅い箇所を比較できるようにする。

組織の実行環境グループでは、このリポジトリだけを選び、公開リポジトリからの利用を許可する。8コアLinux x64は[1ジョブ・1分あたり$0.022](https://docs.github.com/en/billing/reference/actions-runner-pricing)で、待機中は課金されない。組織のActions予算は別途設定する。

8コア環境の短縮幅は、その環境でのCI結果を確認してから記録する。

## 作業の進め方

変更に関係するテストをAirで先に実行する。コミット前の必須確認は`AGENTS.md`のとおり維持する。
push後のCIを待つ間は、独立した実装や文書確認を進める。マージ・本番配備前は対象コミットの結果を待つ。

キャッシュは実際に再利用できる成果物が確認できた場合だけ追加する。現在の音声処理では、専用キャッシュ用のコンパイル成果物は確認できていない。
