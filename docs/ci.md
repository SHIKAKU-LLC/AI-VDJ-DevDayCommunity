# 自動テストの待ち時間

## 確認した所要時間

初回の[GitHub Actions実行](https://github.com/hapx2yuki/AI-VDJ-DevDayCommunity/actions/runs/39055232886)は全項目が成功した。

| 確認 | 所要時間 |
| --- | --- |
| ファイル検査・Python | 48秒 |
| ブラウザ・ルーム | 4分26秒 |
| 音声解析・処理連携 | 6分52秒 |

ブラウザ・ルームのうち4分17秒がテスト本体、依存関係の導入は約3秒だった。現時点ではダウンロードの再利用より実行の並列化を優先する。

## 設定

- ブラウザ・ルームと音声連携は、それぞれ2ファイルずつ実行する。
- 同じブランチ・PRへの新しい更新が来たら、古い実行を停止する。
- 音声処理内部の計算スレッドは1にし、過剰な並列化を避ける。
- 試験の一覧と標準ランナーの種類は維持する。有料の大型ランナーは追加しない。
- 数値・音声の試験を工程別に表示し、遅い箇所を比較できるようにする。

[非公開リポジトリの標準Linuxランナー](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)は2CPU。
[Node.jsの既定値](https://nodejs.org/dist/latest-v24.x/docs/api/cli.html#--test-concurrency)は利用可能CPU数から1を引くため、並列数を明示する。
変更後の短縮幅は、実際のCI結果で確認する。

## 作業の進め方

変更に関係するテストをAirで先に実行する。コミット前の必須確認は`AGENTS.md`のとおり維持する。
push後のCIを待つ間は、独立した実装や文書確認を進める。マージ・本番配備前は対象コミットの結果を待つ。

キャッシュは実際に再利用できる成果物が確認できた場合だけ追加する。現在の音声処理では、専用キャッシュ用のコンパイル成果物は確認できていない。
