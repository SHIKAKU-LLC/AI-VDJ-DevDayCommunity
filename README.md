# AI VDJ — みんなの言葉で、音と映像を。

**参加者のひとことが、会場の音楽と映像になる。**

AI VDJは、参加者が投稿した言葉や画像から音楽と映像を生成し、ブラウザの大画面で連続再生する、参加型のDJ・VJサービスです。
オーナーが開いたルームにスマホから参加し、その場のアイデアを演出へ加えられます。
1人で自分だけのセッションを作ることも、複数人で会場の雰囲気を変えていくこともできます。

**OpenAI Decisions APIを、みんなに出番を回すために組み込みました。** 投稿順を基本に、同じ人の再採用が続く場面だけ「順番を譲るか」を固定の選択肢で判断します。音楽と映像は12秒のセットでつなぎ、APIを待たずに演出を続けます。[仕組みと確認方法](docs/decisions-playback.md)

> 12秒版を本番へ反映しました。画像モチーフ8本を含む15組、合計3分の待機セットを用意しています。
>
> Decisions連携と投稿受付順への変更は本番未配備です。Decisionsは既定で無効、合成データ・APIモックによる検証済みで、実API応答は未確認です。

**[本番サービスを開く](https://ai-vdj-devdaycommunity.hapx2yuki.workers.dev/room)**

インストール、APIキーの入力、Macとの接続は不要です。ルームの作成から投稿・生成・再生まで、ブラウザだけで体験できます。
大画面で再生する端末はPCのChromeをおすすめします。参加者向けにはスマホから使える投稿画面を用意しています。

## どんな体験を作るのか

会場で音楽を聴き、映像を眺める人が、自分のアイデアを演出へ加えられるようにします。
専門的な音楽用語や長い生成指示は必要ありません。「宇宙を走る重低音」のような短い言葉から、サービス側が音作りと映像の演出を組み立てます。

たとえば、オーナーが「ネオンの猫が踊る」と投稿して再生を始め、別の参加者が「液体金属の宇宙」と投稿すると、完成した音楽と映像が次の演出へ加わります。
画像を添えれば、そのキャラクターや人物の特徴を生かした映像にも展開できます。
生成・待ち時間・切り替えまでを、一つの会場体験として設計しています。

| 体験の特徴 | 利用者にとっての意味 |
| --- | --- |
| 短いプロンプトで参加 | 詳しい生成指示を書かずに、自分のアイデアを送れます |
| 画像は任意 | 言葉だけでも成立し、画像があれば被写体の特徴を演出へ加えられます |
| 音楽と映像を一緒に生成 | 一つの投稿から、そのイメージに沿う音と映像を作ります |
| みんなの投稿を公平に採用 | 音楽と映像を12秒単位でつなぎ、採用回数が少ない人を優先します |
| OpenAI Decisions APIで出番を調整 | 同じ人の繰り返し投稿を後へ回し、ほかの参加者にも出番を作ります。保留した投稿もキューに残ります |
| 生成待ちでも演出を継続 | 再生開始後は、手元にある音楽と承認済み映像を使って次の完成を待てます |
| ブラウザだけで利用 | 専用アプリや生成サービスのアカウントを利用者に求めません |

## 審査・体験用の使い方

1. **ルームを作る**

   [本番サービス](https://ai-vdj-devdaycommunity.hapx2yuki.workers.dev/room)を開き、「ルームを開く」を押します。その端末がオーナーの再生画面になります。
2. **参加者を招待する**

   「みんなを招待・受付設定」を開き、QRコードを読み取るか、「URLをコピー」で参加用URLを共有します。参加者は呼ばれたい名前を入力し、「参加する」を押します。
3. **プロンプトと、任意で画像を投稿する**

   「ネオンの猫が踊る」「宇宙を走る重低音」など、短い言葉を入力します。画像を使う場合だけ「画像を添付」から添付し、「送る」を押します。画像なしでも生成できます。オーナー自身も「生成する」から投稿できるため、1人でも試せます。
4. **生成を待つ**

   投稿を受け付けると、サーバーが音楽12秒と映像12秒を各1本生成します。「生成状況」で進み具合と採用回数を確認できます。オーナー画面を閉じても生成は続きます。生成時間は外部サービスの混雑状況で変わります。
5. **音楽と映像を大画面で楽しむ**

   準備完了後、オーナー画面で「再生する」→四隅の拡大アイコンを押します。投稿の完成前はプリセットを流し、完成後は次の12秒の区切りから投稿の音楽・映像へ切り替わります。

### おすすめの試し方

- **言葉だけで試す**：「宇宙を走る重低音」で、共通のDJ・VJ演出と投稿したテーマの組み合わせを確認します。
- **画像を添えて試す**：キャラクターなどの画像に「ネオンのステージで踊る」と添え、被写体の特徴と動きが映像へどう反映されるかを見ます。
- **2人以上で試す**：1台を再生画面、もう1台を参加者画面にして、投稿から生成・演出への追加までを体験します。
- **再生を続けて試す**：曲の切り替え、複数の映像、生成待ちの間の演出を通して確認します。

繰り返し投稿できます。1ルーム最大100投稿で、イベント全体の残予算にも上限があります。再生中はオーナーのタブを開いたままにしてください。
全画面の解除は**Esc**、再生の停止は「停止」です。
生成費用は運営側が負担し、参加者への請求はありません。審査用の受付期間・生成枠には上限があります。

## 操作卓の使い方

- **再生と停止**：音楽と映像の準備ができたら「再生する」を押します。「停止」で止められます。
- **大画面**：四隅の拡大アイコン、または `F` キーで全画面を切り替えます。解除は `Esc`。操作部分はポインターを動かすか、キーボードでフォーカスすると表示されます。
- **出力音量**：フェーダーで0 dB〜−60 dB（下端は無音）に調整できます。矢印キーでも操作でき、ダブルクリックで0 dBに戻ります。スピーカーボタンのミュート中も曲と映像は進みます。
- **出力メーター**：音量調整後の左右の実信号を表示します。
- **明暗**：右上の切り替えからダーク・ライト・端末設定を選べます。初期表示はダークです。再生や入力内容は保たれます。
- **スマートフォン**：「映像」「投稿」「生成状況」のタブで切り替えます。表示を切り替えても再生は止まりません。参加者には投稿と生成状況が表示されます。
- **招待と受付**：「みんなを招待・受付設定」で参加用QRコードと投稿の受付を操作できます。生成は投稿の受理後に自動で始まります。

操作画面は[audiocn-dsの公式規則](https://audiocn-ds.vercel.app/docs/ai/design-rules)に沿い、Stone配色と機材の操作卓を思わせる部品で統一しています。映像作品の表現はそのままに、投稿・生成・再生の状態を見分けやすくしています。[利用部品とライセンス](room-web/console/THIRD_PARTY.md)

## 体験の見どころ

### 1. 一人の投稿を、12秒の見せ場にする

音楽12秒と映像12秒を各1本生成し、必ずセットで再生します。
EDM・サイケデリックトランスを軸に、140 BPM・4拍子・A minorを共通の制作指示にしています。
キックと重低音、印象的なフレーズを冒頭から鳴らし、長い導入で12秒を使い切らないよう指示します。
これらは生成モデルへの制作指示であり、すべての出力が指定どおりになる保証ではありません。

完成した投稿の中では、まだ採用されていない人、採用回数が少ない人を優先します。
同数ならサーバーが受け付けた投稿順です。同じ人が続くときは、再生可能な別の参加者の最も早い投稿へ譲ります。再生開始の記録は一度だけ加算し、再読み込みや再送で重複しません。

実装：[音楽の制作指示](cloud/cloudflare/creative-direction.mjs) / [公平な再生順](cloud/cloudflare/playback-queue.mjs)

### 2. 新しい投稿を優先し、待ち時間にも変化を作る

映像はMiniMax H3 Maxの1080Pで生成します。
音楽と映像の両方が揃った投稿を、共通の12秒の時計で切り替えます。
先に投稿された一件が遅れていても、別の完成済み投稿を流せます。

待機用には、画像モチーフ8本と抽象映像7本に、新しい12秒音楽を組み合わせた15組（合計3分）を用意しています。最大38組まで対応できます。
一巡するまでは同じセットを選び直さず、投稿が準備できたら次の区切りから投稿を優先します。
再生中の音も解析し、生成映像に重ねる光や図形の動きへ反映します。

実装：[12秒単位の連続再生](room-web/judge-set-player.mjs) / [音に反応する描画](room-web/judge-vj.mjs)

### 3. 画像から演出指示を自動で作る

添付画像がある場合は、Cloudflare Workers AIで被写体の特徴・色・画風を読み取り、映像用の制作指示へ組み込みます。
利用者が「この眼鏡を残す」「ドット絵のまま動かす」といった詳細を毎回書く必要はありません。

人物・イラスト・ドット絵などに応じて、姿勢や表情、体の動きを指示します。
光、影、粒子との関わりも指定し、被写体が周囲のサイケデリックな空間へ馴染むことを目指します。
画像がない投稿では、この解析を省いて、言葉から直接生成を進めます。

実装：[画像から特徴を読み取る処理](cloud/cloudflare/image-direction.mjs) / [被写体に応じた演出指示](cloud/cloudflare/creative-direction.mjs)

### 4. 生成の遅さを、再生の停止に直結させない

30人分の投稿について音楽と映像の依頼を並行して進めます。実際に同時実行される数はfal側の契約枠・モデルの混雑状況に従います。
生成、取得、形式調整、品質検査、再生準備を段階として管理し、完成した素材から利用します。
再生画面は生成完了を待って音を止める設計にはせず、保存済みの音楽・映像を使って演出を続けます。
最初は待機用プリセットの読み込みが終われば再生を始められます。ブラウザの制約により、最初の「再生する」操作は必要です。

実装：[生成処理の進行管理](cloud/cloudflare/generation-runtime.mjs) / [ブラウザへの素材読み込み](room-web/judge-controller.mjs)

### 5. OpenAI Decisions APIで、みんなの出番を支える

DevDayの技術要素として、**Decisions APIの`choice`**を次の再生セットの選択に採用しました。文章を生成する処理を再生の間に挟む必要がなく、「先頭を再生する／繰り返し分を後へ回す」という限定した判断を扱えます。

たとえばAさんが2回、Bさん・Cさんが1回ずつ送った場合、全件の準備ができていれば次の順番になります。

```text
投稿：A1 → A2 → B1 → C1
再生：A1 → B1 → C1 → A2
```

基本の投稿順と一巡のルールはサーバーが保持します。APIは採用回数・直前と同じ参加者かどうかなどの数値・真偽値から、順番を譲る場面を判断します。投稿文・画像・名前は送らず、作品の好みや人気で順番を変えません。別の人が待っていなければ、そのまま次の投稿を再生できます。

問い合わせは現在のセットを流している間に行います。APIが遅い・失敗した・ルールに反する回答を返した場合も、サーバーの同じ公平ルールで次を選びます。音楽と映像の組み合わせ、12秒の切り替え、待機中のプリセット再生を維持します。

実装：[Decisions APIへの問い合わせ](cloud/cloudflare/playback-decisions.mjs) / [再生候補の検証](cloud/cloudflare/playback-queue.mjs) / [事前問い合わせと重複防止](cloud/cloudflare/audience-room.mjs)

仕様：[`POST /v1/decisions`・`gpt-6-luna`の公式ガイド](https://developers.openai.com/api/docs/guides/decisions) / [設定・検証範囲](docs/decisions-playback.md)

## 技術構成

```text
オーナー・参加者のブラウザから、言葉と任意の画像を投稿
    ↓
Workersで受付・権限確認 ／ D1でルーム・投稿・費用を記録
    ↓
Durable Objectsで生成を管理（画像ありの場合はWorkers AIで特徴を解析）
    ↓
fal.aiで音楽・映像を生成 → Containersで形式調整・品質検査
    ↓
非公開R2へ保存 → オーナーのブラウザへ配信
    ↓
投稿順・採用回数から次の候補を準備
    ├─ 繰り返し採用の調整：OpenAI Decisions APIへ事前問い合わせ
    └─ サーバーで回答を検証。未着・失敗時も同じ公平ルールで選択
    ↓
大画面で連続再生・曲と映像の切り替え・音に反応する描画
```

| 担当 | 技術・実装 |
| --- | --- |
| 画面とAPI | React 19.2、audiocn-ds、Tailwind CSS v4、Base UI、Cloudflare Workers |
| ルーム・投稿・費用予約 | Cloudflare D1 |
| 受付・公平な再生順／投稿ごとの生成処理 | Cloudflare Durable Objectsを分離して管理 |
| 繰り返し採用時の選択 | OpenAI Decisions API / `gpt-6-luna` / `choice`。固定ルールで検証し、失敗時は即座に代替 |
| 画像の特徴解析 | Cloudflare Workers AI / Moondream |
| 音楽生成 | fal.ai / Stable Audio 3 |
| 映像生成 | fal.ai / MiniMax H3 Max。画像の有無で生成方法を切り替え |
| 形式調整と検査 | Cloudflare Containers / Node.js・Python・ffmpeg |
| 素材の保存 | 非公開のCloudflare R2 |
| 曲と映像の連続再生 | Web Audio API、HTML video、Canvas |

生成モデルとクラウド側の処理はサービスが管理します。
利用者の端末は、ブラウザで投稿や再生を担当します。

## 継続して使うための設計

- **生成費用の管理**：生成前に料金・残高・予約上限を確認し、ルームとイベント全体の枠をD1で管理します。
- **重複生成の防止**：送信記録と生成の進行状態を保存します。結果が不明な有料要求を自動で送り直さず、確認が必要な状態として止めます。
- **素材の品質検査**：音量・形式を調整し、動画の黒画面、静止状態、急激な明暗変化などを検査してから再生用素材として渡します。
- **権限の分離**：オーナーと参加者の操作範囲を分け、別のルームの操作や素材取得を拒否します。APIキーはサーバー側で管理します。
- **画像の扱い**：投稿画像は画像解析と映像生成に使用します。通常の参加者の画像を、ほかのルームの共通プリセットへ自動追加することはありません。
- **入力と指示の分離**：投稿された言葉や画像内の文字を、共通の制作方針やシステム設定を変更する指示として扱わない構成にしています。

自動テストと、生成・再生の実動作は分けて確認しています。12秒版の[実装・検証記録](docs/audience-twelve-second.md)も公開しています。

| Decisions連携 | 合成データで投稿順・一巡・保留後の採用、APIモックで固定選択肢・失敗時の継続・古い応答の拒否・再起動時の重複防止を確認。実API応答と本番配備は未確認 |

生成結果や待ち時間は投稿内容・外部サービスの状態によって変わります。
画像の顔・形・画風が完全に一致する保証はありません。
別ブラウザ・外部モニター接続での確認は含みません。

## 開発者向けのローカル検証

以下は開発用の手順です。本番サービスを体験するだけなら実行する必要はありません。

Node.js 24、Python 3.11、ffmpegを使います。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r qa-tools/runtime-requirements.txt
npm ci --prefix qa-tools --ignore-scripts --no-audit --no-fund
npm ci --prefix snapshot --ignore-scripts --no-audit --no-fund
npm ci --prefix cloud/cloudflare --ignore-scripts --no-audit --no-fund
npm ci --prefix room-web/console --no-audit --no-fund
npm test --prefix room-web/console
npm run build --prefix room-web/console
python3 -m unittest discover -s tests -v
node --test --test-concurrency=4 --test-timeout=120000 tests/*.test.mjs snapshot/app/runtime/*.test.mjs integration/mac-host/*.test.mjs
```

テストに実際の音源、外部API、APIキー、有料生成は必要ありません。
音声処理を含む検証では`.venv/bin`を`PATH`へ追加するか、`VDJ_QC_PYTHON`でPythonの実行ファイルを指定してください。
